# مدیریت بکاپ توکسر

**پلتفرم سازمانی پشتیبان‌گیری و بازیابی برای سرورهای لینوکس**

توسعه‌یافته توسط **TokserTeam**

Tokser Backup Manager (TBM) یک نرم‌افزار خودمیزبان برای پشتیبان‌گیری از سرورهای
لینوکس است. از طریق یک پنل تحت وب مدرن می‌توانید هر تعداد مسیر دلخواه را تعریف
کنید، برای هر کار زمان‌بندی مستقل بسازید، آرشیوهای فشرده و در صورت نیاز رمزنگاری‌شده
تولید کنید، آن‌ها را به فضای ذخیره‌سازی خارجی یا تلگرام ارسال کنید، فایل‌ها را
به‌صورت انتخابی بازیابی کنید و همه اتفاقات را ثبت و بررسی کنید.

## ویژگی‌ها

### موتور بکاپ
- تعداد نامحدود منبع در هر کار — فایل، پوشه و دیتابیس
- الگوهای استثنا برای هر منبع و هر کار (`*.log`، `.git`، `node_modules` و …)
- فرمت‌های TAR، TAR.GZ، ZIP و Zstandard با سطح فشرده‌سازی قابل تنظیم
- رمزنگاری اختیاری آرشیو با AES-256-GCM
- بررسی صحت آرشیو پس از ساخت (خواندن کامل تمام اعضا)
- محاسبه و ذخیره checksum SHA-256 برای هر آرشیو
- پیاده‌سازی Streaming — آرشیو هرگز به‌طور کامل در RAM بارگذاری نمی‌شود
- امکان لغو عملیات و پاک‌سازی خودکار فایل‌های ناقص
- حفظ مجوزها، مالکیت، زمان و لینک‌های نمادین
- محدودیت تعداد عملیات هم‌زمان و جلوگیری از اجرای تکراری یک کار

### زمان‌بندی
- دستی، هر N دقیقه، هر N ساعت، روزانه، هفتگی، ماهانه یا Cron سفارشی
- منطقه زمانی مستقل برای هر کار با محاسبه صحیح تغییر ساعت تابستانی
- تاریخ شروع و پایان، توقف و ادامه
- ذخیره زمان اجرای بعدی در دیتابیس، بنابراین زمان‌بندی پس از Restart حفظ می‌شود

### بازیابی
- مشاهده محتوای واقعی آرشیو پیش از بازیابی
- بازیابی کامل یا انتخابی بر اساس مسیر
- جلوگیری از Path Traversal و Zip Slip
- امکان گرفتن بکاپ ایمنی از مقصد پیش از بازنویسی
- نمایش پیشرفت زنده و تاریخچه هر بازیابی

### نگهداری نسخه‌ها
- نگهداری N نسخه آخر، نگهداری به مدت N روز، یا هر دو
- حذف خودکار نسخه‌های قدیمی پس از هر اجرای موفق
- جدیدترین بکاپ موفق و بکاپ‌های در حال اجرا هرگز حذف نمی‌شوند
- فایل‌های منبع اصلی هرگز تغییر نمی‌کنند و حذف نمی‌شوند

### ارسال
- دیسک محلی، SFTP، FTP/FTPS و ذخیره‌سازی سازگار با S3 (AWS S3، MinIO و …)
- اتصال به Telegram Bot API با تقسیم خودکار آرشیوهای حجیم
- ثبت وضعیت هر بخش ارسالی — ارسال ناقص هرگز موفق اعلام نمی‌شود
- تلاش مجدد با تأخیر فزاینده برای هر بخش
- رمزنگاری اطلاعات محرمانه در دیتابیس

### امنیت
- هش رمز عبور با Argon2id (پشتیبانی از bcrypt قدیمی با ارتقای خودکار)
- Session سمت سرور با کوکی `HttpOnly` و `SameSite=Lax`
- محافظت CSRF اجباری در Middleware برای تمام درخواست‌های تغییردهنده
- محدودیت نرخ درخواست و قفل حساب پس از تلاش‌های ناموفق
- کنترل دسترسی مبتنی بر نقش (مدیر / اپراتور / بازدیدکننده)
- ثبت کامل رویدادهای امنیتی و عملیاتی
- هدرهای امنیتی و Content-Security-Policy سختگیرانه
- تمام کوئری‌ها با Parameter Binding — بدون هیچ اجرای Shell
- تأیید دومرحله‌ای TOTP (اختیاری)

### عملیات
- داشبورد زنده با آمار، نرخ موفقیت، مصرف فضا و نمودارهای فعالیت
- مانیتورینگ سرور: CPU، حافظه، دیسک، I/O، شبکه و زمان فعالیت
- اعلان درون‌برنامه، تلگرام و ایمیل با کنترل کانال برای هر رویداد
- REST API کامل با مستندات OpenAPI
- خروجی CSV/JSON از تاریخچه و دانلود لاگ

### رابط کاربری
- پنل مدرن و واکنش‌گرا با پوسته تیره و روشن
- پشتیبانی کامل RTL و رابط فارسی در کنار انگلیسی
- رنگ تأکیدی قابل تغییر، اعلان‌های Toast، مودال و پیشرفت زنده
- نمودارها با کتابخانه SVG اختصاصی (بدون وابستگی به CDN خارجی)
- تمام دکمه‌ها به Endpoint واقعی متصل هستند

## پیش‌نیازها

| مورد | حداقل |
|---|---|
| سیستم‌عامل | Ubuntu 22.04 / 24.04، Debian 12+ |
| پایتون | 3.12 |
| حافظه | 512 مگابایت (1 گیگابایت توصیه می‌شود) |
| دیسک | 1 گیگابایت برای برنامه + فضای آرشیوها |
| دیتابیس | SQLite (پیش‌فرض) یا PostgreSQL 14+ |
| سرویس‌دهنده | systemd |
| وب‌سرور | Nginx (توسط نصب‌کننده نصب می‌شود) |

ابزارهای اختیاری برای بکاپ دیتابیس:

| دیتابیس | ابزار |
|---|---|
| MySQL / MariaDB | `mysqldump` یا `mariadb-dump` |
| PostgreSQL | `pg_dump` |
| SQLite | داخلی (با استفاده از Online Backup API) |

## نصب

### نصب خودکار (Ubuntu / Debian)

**یک دستور، مستقیم از گیت‌هاب:**

```bash
curl -fsSL https://raw.githubusercontent.com/OfficialMaziar/TokserBackuper/main/install.sh | sudo bash
```

اسکریپت پروژه را در یک پوشه موقت دانلود می‌کند، نصب‌کننده را اجرا می‌کند و
بعد پاک‌سازی می‌کند. چیزی جز خودِ نصب باقی نمی‌ماند.

برای دادن گزینه، بعد از `-s --` بنویسید:

```bash
curl -fsSL https://raw.githubusercontent.com/OfficialMaziar/TokserBackuper/main/install.sh \
  | sudo bash -s -- --domain backup.example.com --http-port 7676
```

**اگر ریپو private باشد**، توکنی با دسترسی `repo` بدهید. فقط برای دانلود
استفاده می‌شود و هیچ‌جا روی دیسک نوشته نمی‌شود:

```bash
TBM_TOKEN=ghp_xxxxxxxx curl -fsSL <installer-url> | sudo -E bash -s --
```

یا خودتان آرشیو را بگیرید و نصب‌کننده را از آن اجرا کنید:

```bash
curl -fsSL -H "Authorization: Bearer $TBM_TOKEN"   https://api.github.com/repos/OfficialMaziar/TokserBackuper/tarball/main -o tbm.tar.gz
tar -xzf tbm.tar.gz && cd TokserBackuper-* && sudo ./scripts/install.sh
```

اگر می‌خواهید اول اسکریپت را ببینید:

```bash
curl -fsSL https://raw.githubusercontent.com/OfficialMaziar/TokserBackuper/main/install.sh -o tbm-install.sh
less tbm-install.sh
sudo bash tbm-install.sh
```

یا نصب از روی کلون:

```bash
git clone https://github.com/OfficialMaziar/TokserBackuper.git
cd TokserBackuper
sudo ./scripts/install.sh --domain backup.example.com
```

نصب‌کننده این مراحل را انجام می‌دهد:

1. بررسی نسخه سیستم‌عامل و پایتون 3.12+
2. نصب بسته‌های سیستمی (پایتون، ابزارهای آرشیو، کلاینت دیتابیس)
3. ساخت کاربر سیستمی بدون دسترسی `TBM`
4. کپی برنامه در `/opt/tokser-backup-manager`
5. ساخت Virtual Environment و نصب وابستگی‌ها
6. تولید فایل `.env` با کلیدهای تصادفی
7. ساخت ساختار دیتابیس
8. ساخت حساب مدیر (تعاملی، یا در صفحه `/setup`)
9. نصب و راه‌اندازی سرویس systemd
10. پیکربندی Nginx به‌عنوان Reverse Proxy
11. بررسی سلامت برنامه

**پورت‌ها.** نصب‌کننده هنگام اجرا در ترمینال از شما می‌پرسد کدام پورت‌ها
استفاده شوند، و اگر پورت پیش‌فرض اشغال باشد خودکار پورت آزاد پیشنهاد می‌دهد —
بنابراین روی سروری که چند سایت دارد هم بدون تداخل نصب می‌شود:

- **پورت داخلی** (پیش‌فرض `8000`، فقط روی `127.0.0.1`): خود برنامه
- **پورت عمومی HTTP** (پیش‌فرض `80`): سایت Nginx در دسترس از اینترنت

اگر پورت 80 قبلاً در اختیار سایت دیگری باشد، نصب‌کننده روی `8080` (یا پورتی که
وارد کنید) منتشر می‌کند و تنظیمات سایت موجود را دست نمی‌زند. صفحه پیش‌فرض Nginx
تنها وقتی حذف می‌شود که هنوز دست‌نخورده باشد.

گزینه‌های مفید:

```bash
sudo ./scripts/install.sh --no-nginx          # فقط برنامه
sudo ./scripts/install.sh --self-signed       # ساخت گواهی TLS خودامضا
sudo ./scripts/install.sh --port 9000         # پورت داخلی برنامه
sudo ./scripts/install.sh --http-port 8080    # پورت عمومی Nginx
sudo ./scripts/install.sh --non-interactive   # بدون پرسش
```

اجرای مجدد نصب‌کننده به‌عنوان به‌روزرسانی عمل می‌کند و داده‌ها، `.env` و
`config.yaml` را حفظ می‌کند.

### داکر

```bash
cp .env.example .env
# مقدار TBM_SECRET_KEY و TBM_ENCRYPTION_KEY را تنظیم کنید
docker compose up -d
```

پنل روی `http://127.0.0.1:8080` در دسترس است. پوشه‌هایی که باید بکاپ شوند را
به‌صورت read-only زیر `/sources/...` مانت کنید و همان مسیرها را در کارها
استفاده کنید.

### نصب دستی

```bash
sudo useradd --system --create-home --home-dir /opt/tokser-backup-manager tokser
sudo git clone https://github.com/OfficialMaziar/TokserBackuper.git /opt/tokser-backup-manager
cd /opt/tokser-backup-manager

sudo python3 -m venv .venv
sudo .venv/bin/pip install -r requirements.txt

sudo cp .env.example .env
sudo chmod 600 .env
# کلیدها را در .env تنظیم کنید

sudo -u TBM .venv/bin/python -c "from app.main import bootstrap; bootstrap()"
sudo cp systemd/TBM.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now TBM
```

## مدیریت از خط فرمان

نصب‌کننده دستور `tbm` را در `/usr/local/bin` قرار می‌دهد. هر کاری که در پنل
برای کاربران، کارها و بکاپ‌ها انجام می‌دهید، از ترمینال هم ممکن است — وقتی پنل
در دسترس نیست، در اسکریپت‌ها، یا از طریق SSH.

```bash
tbm status                       # وضعیت سرویس، کارها و دیسک
tbm doctor                       # عیب‌یابی تنظیمات
tbm --json status                # خروجی قابل پردازش

tbm user list                    # کاربران، نقش‌ها، وضعیت قفل
tbm user passwd admin            # تغییر رمز (پرسش تعاملی + رفع قفل)
tbm user create ops --role operator
tbm user unlock admin            # رفع قفل پس از تلاش‌های ناموفق
tbm user role ops admin
tbm user disable ops
tbm user delete ops --yes

tbm job list
tbm job show 3
tbm job run 3                    # اجرای فوری
tbm job run 3 --wait             # اجرا و انتظار برای نتیجه
tbm job disable 3

tbm backup list --limit 20
tbm backup show 42
tbm backup verify 42             # بررسی مجدد صحت آرشیو
tbm backup delete 42 --yes

tbm service status | restart | stop | start
tbm service logs -f              # دنبال کردن لاگ

tbm maintenance recalc           # محاسبه مجدد زمان اجرای بعدی همه کارها
tbm maintenance prune-sessions
tbm maintenance vacuum           # فشرده‌سازی SQLite
tbm maintenance check-disk       # کد خروج ۱ وقتی فضا کم است

tbm access grant /root           # دسترسی خواندن /root با ACL (فقط خواندن)
tbm access grant /var/www
tbm access check  /root          # کد خروج ۰ اگر قابل خواندن باشد
tbm access revoke /root
```

نکته‌ها:

- تغییر رمز و سایر ویرایش‌های دیتابیس با کاربر `TBM` اجرا می‌شوند تا مالکیت
  فایل‌ها درست بماند؛ دستورات `service` به root نیاز دارند و خودکار با `sudo`
  دوباره اجرا می‌شوند.
- دستورات مخرب (`delete`) به `--yes` نیاز دارند.
- CLI اجازه نمی‌دهد آخرین مدیر حذف، تنزل یا غیرفعال شود.
- برای دیدن گزینه‌های هر دستور: `tbm <command> --help`
- سرویس با کاربر بدون دسترسی `TBM` اجرا می‌شود. برای بکاپ از `/root` یا پوشه‌های
  با مجوز 0700 از `tbm access grant` استفاده کنید، نه اجرای سرویس با root.

## تنظیمات

تنظیمات به‌صورت لایه‌ای خوانده می‌شوند؛ اولویت از بالا به پایین:

1. مقادیر پیش‌فرض (`app/core/config.py`)
2. فایل `config.yaml` (از `config.example.yaml` کپی کنید)
3. متغیرهای محیطی / `.env`

مهم‌ترین متغیرها:

| متغیر | کاربرد |
|---|---|
| `TBM_DATABASE_URL` | رشته اتصال SQLite یا PostgreSQL |
| `TBM_SECRET_KEY` | کلید امضای توکن و Session — **محرمانه** |
| `TBM_ENCRYPTION_KEY` | کلید رمزنگاری اطلاعات محرمانه — **محرمانه** |
| `TBM_BACKUP_DIR` | مسیر نوشتن آرشیوها |
| `TBM_MAX_CONCURRENT` | تعداد بکاپ هم‌زمان |
| `TBM_SECURE_COOKIE` | در صورت استفاده از HTTPS مقدار `true` |
| `TBM_ALLOWED_HOSTS` | محدودسازی هدر Host |

> **از فایل `.env` نسخه پشتیبان بگیرید.** کلید `TBM_ENCRYPTION_KEY` برای
> رمزگشایی رمزهای ذخیره‌شده ضروری است. بدون آن این اطلاعات قابل بازیابی نیستند
> (خود آرشیوها آسیب نمی‌بینند چون رمز مخصوص خود را دارند).

بسیاری از تنظیمات از داخل پنل و صفحه **Settings** نیز قابل تغییر است.

## اولین اجرا

1. آدرس `https://your-host/` را باز کنید.
2. اگر هیچ حسابی وجود نداشته باشد به `/setup` هدایت می‌شوید.
3. حساب مدیر را بسازید: حداقل ۱۰ کاراکتر شامل حرف و رقم.
4. وارد شوید. داشبورد داده‌های واقعی را نمایش می‌دهد.

هیچ رمز پیش‌فرضی ساخته نمی‌شود.

## راهنمای استفاده

### ساخت کار بکاپ

1. **Backup Jobs → New Backup Job**
2. نام و توضیحات را وارد کنید.
3. منابع را اضافه کنید: روی **+ Add** بزنید و مسیر مطلق را بنویسید یا از
   **Browse** استفاده کنید. وضعیت دسترسی هر مسیر نمایش داده می‌شود.
4. در صورت نیاز الگوهای استثنا اضافه کنید.
5. فشرده‌سازی، سطح، رمزنگاری و سیاست نگهداری را انتخاب کنید.
6. زمان‌بندی را تنظیم کنید (یا دستی بگذارید).
7. **Save** و سپس **▶** برای اجرای فوری.

### زمان‌بندی

| نوع | رفتار |
|---|---|
| Manual | فقط با اجرای دستی |
| هر N دقیقه | فاصله ثابت از اجرای قبلی |
| هر N ساعت | فاصله با دقیقه مشخص |
| روزانه | ساعت و دقیقه مشخص هر روز |
| هفتگی | روز هفته، ساعت و دقیقه |
| ماهانه | روز ماه (در ماه‌های کوتاه به آخرین روز محدود می‌شود) |
| Cron سفارشی | پنج فیلد استاندارد، مثلاً `0 3 * * mon-fri` |

منطقه زمانی هر کار رعایت می‌شود. کاری که در حال اجراست دوباره شروع نمی‌شود.

### بازیابی

1. **Restore Center** را باز کنید یا روی یک بکاپ **Restore** بزنید.
2. ابتدا محتوای آرشیو را بررسی کنید.
3. مسیر مقصد (مطلق) را وارد کنید.
4. در صورت نیاز مسیرهای خاص را وارد کنید (خالی = همه).
5. تعیین کنید فایل‌های موجود بازنویسی شوند یا نه و بکاپ ایمنی گرفته شود یا نه.
6. بازیابی را شروع کنید و پیشرفت را در **Restore history** ببینید.

اعضایی از آرشیو که به بیرون از مقصد اشاره کنند نادیده گرفته و ثبت می‌شوند.

### ارسال با تلگرام

1. با [@BotFather](https://t.me/BotFather) یک ربات بسازید و توکن را بردارید.
2. به ربات پیام بدهید و Chat ID را به دست آورید.
3. **Telegram → Add Telegram Destination** و هر دو مقدار را وارد کنید.
4. **Test** توکن را بررسی می‌کند؛ **Send test** یک پیام واقعی می‌فرستد.
5. در کار موردنظر گزینه **Upload archive to Telegram** را فعال کنید.

فایل‌های بزرگ‌تر از ۴۹ مگابایت به‌صورت خودکار تقسیم می‌شوند. نتیجه هر بخش
ثبت می‌شود و ارسال ناقص با وضعیت `partial` ذخیره می‌شود، نه موفق.

## امنیت

- رمزها با Argon2id هش می‌شوند
- Session سمت سرور؛ فقط هش SHA-256 توکن ذخیره می‌شود
- CSRF برای تمام تغییرات با Cookie اجباری است
- محدودیت نرخ درخواست و قفل حساب
- RBAC روی تمام Endpointها
- ثبت کامل رویدادهای امنیتی
- جلوگیری از Path Traversal و Zip Slip
- هیچ اجرای Shell؛ تمام دستورات با آرگومان کامل
- سرویس با کاربر بدون دسترسی اجرا می‌شود

برای دسترسی به فایل‌های متعلق به root، عضویت گروهی بدهید نه اجرای با root:

```bash
sudo tbm access grant /var/www
sudo tbm service restart
sudo tbm access check /var/www
```

برای `/root`:

```bash
sudo tbm access grant /root
```

## معماری

```
app/
├── main.py          # برنامه FastAPI، Middleware، Bootstrap، مسیر صفحات
├── core/            # config، database، security، logging
├── models/          # موجودیت‌های SQLAlchemy
├── schemas/         # مدل‌های Pydantic
├── api/             # Routerها و Dependencyهای مشترک
├── services/        # backup، archive، restore، cron، retention،
│                    # storage، telegram، db dump، monitoring
├── templates/       # صفحه ورود، راه‌اندازی و قالب SPA
└── static/          # CSS، ماژول‌های JS، آیکون‌ها
```

**جریان درخواست:** مرورگر → Router → Dependency (Session، CSRF، RBAC) →
لایه سرویس → SQLAlchemy → دیتابیس. عملیات سنگین (بکاپ و بازیابی) در Thread
جداگانه با Session مستقل اجرا می‌شود. زمان‌بند یک Thread واحد است که مقادیر
`next_run_at` ذخیره‌شده در دیتابیس را بررسی می‌کند.

## تست

```bash
# با pytest (توصیه‌شده)
pip install pytest
pytest tests/ -v

# در محیط بدون اینترنت
python tests/run_tests.py -v
```

پوشش تست‌ها: پارس Cron و محاسبه اجرای بعدی در تمام انواع زمان‌بندی و مناطق
زمانی، ساخت/بررسی/استخراج آرشیو در چهار فرمت، رمزنگاری و رمزگشایی، رد
Zip Slip و Path Traversal، پاک‌سازی پس از لغو، هش رمز و TOTP، CSRF، RBAC،
CRUD کارها، تعداد زیاد منابع، اجرای بکاپ، جلوگیری از هم‌پوشانی، حذف نسخه‌های
قدیمی، بازیابی، حفظ تنظیمات و هدرهای امنیتی.

## به‌روزرسانی

```bash
cd /opt/tokser-backup-manager
sudo ./scripts/install.sh    # به‌روزرسانی در محل با حفظ داده‌ها
```

یا به‌صورت دستی:

```bash
cd /opt/tokser-backup-manager
sudo -u TBM git pull
sudo -u TBM .venv/bin/pip install -r requirements.txt
sudo -u TBM .venv/bin/alembic upgrade head
sudo systemctl restart TBM
```

پیش از به‌روزرسانی از دیتابیس نسخه پشتیبان بگیرید:

```bash
sudo -u TBM sqlite3 data/tokser.db ".backup '/root/tbm-$(date +%F).db'"
```

## رفع خطا

| نشانه | علت و راه‌حل |
|---|---|
| خطای «No files matched» | مسیر وجود ندارد یا کاربر سرویس دسترسی ندارد. دسترسی گروهی بدهید |
| «Permission denied» روی منبع | کاربر `TBM` دسترسی خواندن ندارد |
| وضعیت `partial` در تلگرام | برخی بخش‌ها ارسال نشده‌اند. توکن، Chat ID و حجم فایل را بررسی کنید |
| سرویس بالا نمی‌آید | `journalctl -u TBM -n 50` |
| «Account locked» | پنج تلاش ناموفق، قفل ۱۵ دقیقه‌ای |
| نمودارها خالی‌اند | هنوز داده‌ای نیست؛ یک بکاپ اجرا کنید |

اسکریپت `./scripts/healthcheck.sh` در صورت سلامت کد خروج ۰ برمی‌گرداند.

## نقشه راه

مواردی که در این نسخه پیاده‌سازی **نشده‌اند** و در رابط کاربری نیز به‌عنوان
قابلیت فعال معرفی نمی‌شوند:

- **بکاپ افزایشی و تفاضلی** — ساختار متادیتا (`backup_files`) و فیلد
  `backup_mode` آماده است، اما موتور فعلاً فقط بکاپ کامل انجام می‌دهد.
- **مدیریت چند سرور** — جدول `servers` و ثبت سرور محلی وجود دارد، اما
  انتقال و احراز هویت Agent پیاده‌سازی نشده است.
- **رابط ثبت دومرحله‌ای** — تأیید TOTP پیاده‌سازی و اعمال می‌شود، اما صفحه
  ثبت (QR) ساخته نشده است.
